# 有序增量名称源实验：不采用

2026-10-28。正式代码及构建保持 index-D4TfdCvK.js，名称缓冲512。
控制器与恢复基线逐字节一致，构建指纹也再次核对。

检查已安装的 MapLibre 6.15.0 实现后，在浏览器响应中隔离替换名称源的 setData：首次完整提交，随后保留完全相同的前缀，删除旧后缀并按新顺序添加后缀。仅使用公开 updateData 接口；未引入产品代码。
前缀以完整要素（包含几何和全部属性）比较，避免仅比较名称而漏掉变化，也避免任意删增改变名称避让次序。

六种相机状态×概览/高速/城轨18组比较中，无名称身份增减或超过1 CSS px的命中范围差异；每组均有真实标注。
候选每次完成后公开 getData 返回的完整集合与预期内容、次序相同。
这是有限静止状态检查，不证明连续运动、快速排队、故障恢复或所有瓦片边界。

相同Chrome156.0.8078.48、1440×1000、10Mbps/100ms、关闭底图、默认绘制器，同机串行，每场景100次真实筛选：

| 名称源方案 | 概览 render p95 | 站场 render p95 |
| --- | ---: | ---: |
| 当前完整替换 | 91.1ms | 40.8ms |
| 保留前缀并增量替换 | 109.4ms | 63.6ms |

概览交替切换通常仅保留35个前缀要素；站场可保留18个、只增删其余13个，仍未观察到收益。
位置检查按概览→高速→城轨顺序切换，其前缀均为0；不能用该序列代表交替切换的复用率。
对照站场最大值838.8ms完整保留，没有剔除慢样本；单轮顺序实验不证明所有条件下的因果或稳定差值。
目前没有采用依据，故不修改正式路径，也没有为已拒绝候选继续制作产品构建或完整浏览器回归。

同时补齐未修改正式构建的30秒闭合站场拖动：默认/软件绘制 render间隔p95为35.0/37.0ms，仍超过33ms目标；两次时长与终点守卫均通过，长任务均为0。
rAF估算掉帧率分别为6.76%/46.93%；软件路径rAF p95为33.4ms，不能拿它替代37.0ms的render间隔。
这两次不是增量候选的平移对照，也不是物理GPU/显示或真实设备验收。
