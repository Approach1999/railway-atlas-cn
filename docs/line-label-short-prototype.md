## 同源片段恢复

新增 line-label-fragments.ts：只对 typed ID 和全部属性相同、端点重合的片段恢复路径。
端点键允许约 0.1 mm 级地理序列化误差；不跨越瓦片泛化造成的缺口，不吸附相近轨道，
不按名称连接不同 way，不处理不能证明的内部重叠。相同/反向片段去重；
端点存在分叉歧义时不接续，闭环明确终止。所有原输入保持不变。

四份真实捕获中，分别恢复 169/134/7/0 处同源端点接续。
优化属性分组后四份候选 JSON 与优化前字节相同，未以更宽松相等规则换取速度。

## 短片段补标

原概览中，于揽三线最大原片段约 45.39 CSS px、浑揽线约 26.08 px，
单一源 ID 的全部重复片段长度相加也不足以安全排下完整沿线文字。
不能为凑长度而连接不同同名对象。
原型对无法容纳沿线文字的片段，提供锚定自己路径中点、沿局部切向直排的独立字幕候选；
不添加轨道几何，不折字，不改变来源 ID。长片段仍使用自己的沿线窗口，优先于短片段字幕。
两者共用基于来源身份的 304 CSS px 候选距离控制。

字幕使用独立点标签层，沿线名称使用 line-center 层，均沿用正常碰撞避让。
点标签携带原 osm_id；尚未接入产品点击路径，不能直接把点标签当作轨道几何交给现有要素校验器。
后续必须显式解析回原轨道/详情，验证选中及分享身份。

## 为什么仍不采用

实际截图的字幕明显增多：重复文字来自不同源 way，虽然没有被错误合并，视觉上仍较拥挤；
某些字幕与相邻轨道交错。当时曾归因于极短泛化片段的局部方向，后续确认零宽度逐字折行是重要原因，
方向本身的可靠性仍未独立证实，不能沿用旧判断作为结论。
图面需要更好的优先级、稳定方向和低缩放密度控制，不能以种类数或源 ID 数替代可读性。
尚未验证动态平移/缩放、完整筛选/版本接线、点击身份、缓存/取消和性能预算。
这些是原型未完成项，不是对 R17 的豁免。正式地图没有使用该模块。

第一版纯沿线算法已按原构建登记 SHA-256 恢复为历史文件，并以该原文件重放旧四份输入，
得到原候选字节。历史 JSON 没有改写；新原型保留独立目录和证据，避免用新算法解释旧结果。
