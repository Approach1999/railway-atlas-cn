## 名称与点击

名称使用独立 GeoJSON 源和四个名称层：主线名称/短注记从 z8 开始，站场与专用线名称/短注记从 z12 开始。
只接续同来源 ID、同属性且端点重合的片段；不同同名来源不连接。
较长路径使用 line-center，使引擎不会在 line 模式下先按文字合并不同来源路径。
短片段使用单行字幕与短引线，共同参与碰撞避让。

同身份候选保留至少 304 CSS 像素间距，给源量化留出余量；这不表示任意两个同名而不同来源的标签都必须相距 300 像素。
正式产品四幅画面共观察到 46/51/13/6 个画内文字锚点；两幅概览没有同身份重复对，站场 11 对最短 308.31 像素，电车 2 对最短 323.18 像素。
43 个至少三个中文字的短字幕框通过宽大于高的检查。这是四幅固定画面的证据，不代替所有视图的易读性与覆盖验收。

点击名称会通过已登记的 label_id 和原始 osm_id 找回该来源的实际 LineString，字幕 Point 不作为轨道几何。
当前与上一代映射最多保留两代，以支持替换期间仍在显示的名称；切换数据版本会清理映射。
实际点击苏抚线 `way/136823634`、分享及重新打开，均保持原来源身份。

## 动态更新与故障

筛选、移动、缩放和瓦片更新触发重新生成；同一内容不重复提交。
缩放时先隐藏旧名称，直到新一代绘制就绪；新增测试覆盖了筛选更新意外重新显示旧名称的竞态。
名称源单独显示加载/错误与重试，15 秒截止；轨道和已加载详情仍可用。
初次名称失败需要主动重绘，才能发布含部分失败状态的首个可用标记；该问题已修复并保留失败记录。

绘制线程仅接收文字、身份与筛选字段；完整来源属性和实际轨道几何保留在有界点击映射中。
这样避免为每个文字候选重复传递完整审计属性。轨道源、分享状态及详情所用记录保持一致。

## 当前性能

最终构建重新执行 30 次冷启动，首个可用视图 median 1.848、p95 1.942、max 1.949 秒；
搜索索引 p95 1.063 秒已包含在首屏等待中，自有传输量每次 694,902 字节。
每次均验证完整 41 层、名称资源 ready/source_loaded；缓存关闭、每次新建隔离上下文。
这仅满足本机关闭底图的桌面测量条件，不能直接关闭完整 N01。

在同一本机默认 Intel Arc 渲染、1440×1000、10 Mbps/100 ms、关闭底图且无第三方请求的条件下，
两个场景各执行 100 次实际预设切换。裁剪绘制字段前/后，概览源就绪绘制 p95 为 182.4/145.6 ms，
站场为 64.3/50.1 ms。当前概览控件应用 p95 为 57.0 ms，不能用它代替 145.6 ms 的地图绘制完成。
概览仍超 N02 的 100 ms 目标；旧管线之前观测为 71.0 ms，因此本次有明确性能回退，仍需优化。
两轮顺序测量显示字段裁剪后的时间较低，但单机两轮结果不足以隔离全部环境波动。

当前站场固定 30 秒闭合拖动：3585 个 render 间隔，median 8.3、p95 8.8、max 29.3 ms；
0 个 >50 ms 长任务，rAF 代理估计掉帧比例 0.000277。闭合轨迹通过端点误差检查。
这些事件是浏览器提交/调度代理，不等于物理显示完成；没有关闭历史软件渲染或真实设备性能缺口。
