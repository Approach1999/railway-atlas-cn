# 手机局域网HTTP详情与底图修复

2026-11-02。用户真机截图显示底图失败、打开搜索结果时报 `Cannot read properties of undefined (reading 'digest')`。
截图是问题报告，不是通过证据；最终仍需用户手机复测。

## 详情根因与修复

地图详情和文字列表均直接调用 `crypto.subtle.digest`，用于将typed OSM ID映射到既有SHA-256首字节分片。
局域网HTTP不属于安全上下文，SubtleCrypto不可用；localhost测试因被浏览器视为可信来源而未暴露问题。
这不是搜索索引损坏，也不是数据完整性校验失败。

两处统一改用纯JS的 `detailShard`，输出仍为完全相同的SHA-256首字节；不改数据目录、快照、详情身份校验或记录内容。
独立Node crypto对照覆盖3000个typed ID、真实站点ID、UTF-8及跨块填充边界。
真正的非回环HTTP浏览器验证确认 `isSecureContext=false`、SubtleCrypto缺失时，搜索与文字列表都能读取沈阳北记录的 `5d.json` 分片。

## 底图试用转发

电脑能获取当前沈阳区域的OSM瓦片，但手机出现外部底图失败；手机网络路径的具体失败原因未由截图单独证明。
增加可选 `--basemap-proxy`：浏览器请求同源 `/preview-basemap/{z}/{x}/{y}.png`，由电脑向固定的OSM HTTPS图源转发。
默认直连配置不变；只有显式启用的本地服务才返回转发配置。客户端仅接受明确标记和固定路径，不接受任意HTTP图源。

```powershell
.\start-preview.cmd --lan --basemap-proxy
```

保留OSM署名，使用明确的应用User-Agent，并按网站的跨域策略仅转发Referer源地址，不转发搜索/视图查询。
本地忽略目录缓存遵循max-age/Age/Expires，过期以ETag/Last-Modified重新验证；no-store不保存并清除旧缓存。
仅允许z0–19及该层有效坐标，固定上游，无任意URL、预取、区域下载或离线打包入口；同时最多4个上游请求。
这是本地人工试用的连接方式，不是公开托管或底图供应方案的验收。依据[OSM瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。

## 缩放后底图消失的后续修复

手机反馈缩放后再次出现底图不可用。客户端原先收到任意一块栅格瓦片错误就删除整个底图源，导致已加载图像丢失，后续缩放也无法恢复。现在保留底图源和已加载图像，提示加载不完整；后续瓦片成功时自动恢复状态。首次加载超时也保留请求，允许迟到的成功响应恢复。手动重试与关闭底图仍可用。单次上游请求为何失败尚未确认。

124项前端测试与严格TS/构建通过。`scripts/verify_basemap_zoom.cjs` 在390px触控模拟中分别注入缩小、放大后的502故障，再继续缩放，验证无需点击重试即可恢复；最终复跑44次成功与19次失败请求均为本地夹具，未向公共图源产生自动缩放流量。此修复晚于上方指纹归档，不应套用其构建哈希或视为真机已复验。

最终构建与源文件指纹、LAN详情及隔离瓦片缓存后的缩放复跑见[最终修复证据](evidence/mobile-final-20261102.json)。首次合并运行的缩放脚本因放大/缩小复用已访问层级的缓存而等待故障提示超时；脚本已改为每个方向重新打开页面隔离MapLibre缓存，复跑通过。受限执行环境的本机网络访问拒绝曾使启动器两项报错，允许本机网络后8项通过；未以修改产品绕过检查。
