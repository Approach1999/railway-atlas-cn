## 重复间距仍未通过

直接读取锁定 MapLibre 6.15 的源码：沿线 symbol-spacing 是候选布点的曲线距离，
桶内相同文字的排重距离为其一半；不能把参数 350 当作屏幕上至少 350 CSS px。
本轮只读诊断枚举实际 placement，排除跨瓦片重复实例、屏外和未完成渐入的文字，
并用公开 queryRenderedFeatures 核对每一条观察到的源对象。
对八个固定画面作同样观察，没有用私有结构修改产品行为。

当前参数的反例：同一源 way/471524857 的两个锚点，在 z10 相隔 191.78 CSS px，
在 z10.5 相隔 271.22 CSS px，均低于设计 300 CSS px。两例来自同一瓦片，
不能由此声称已测到或解决跨接缝问题。锚点距离也不等于字形边界间距或物理屏幕像素。

仅在浏览器响应副本中将间距改为 600：八个画面未出现上述近距离对，但标签关联的源 ID 集合发生变化。
例如 z10 原关联 21 个源 ID，候选为 16 个，失去 7 个原 ID、增加 2 个；
z11 原关联 25 个，候选为 18 个。后续发现引擎会先按同字/端点拼接路径，再保留其中一个 ID，
所以此计数不能单独证明独立源对象的名称覆盖变差，亦不等于完整线路数量。
引擎还会按文字排重，简单加大参数不能证明满足基于来源身份的排重要求，故候选没有采用。
生产参数仍为 350。下一步需要保留源身份的名称候选/重复控制，并验证接缝和双线，而非以减少文字总量代替验收。
上述推断更正和独立身份原型的真实名称集合比较见 [来源身份原型](line-label-prototype.md)；旧构建 JSON 留存原始记录。

初次诊断误将 placement 中渐入起始 opacity 当作当前 opacity，导致有效锚点数为零。
修正为等待源与 placement 稳定、使用引擎 symbolFadeChange 计算当前 opacity，再完整执行两组八画面对照。
早期零计数未作为通过证据。原生库内部字段变化时诊断直接失败，不静默给出结论。

本轮未重测性能、实际 200%、字体缺字、完整对比度/读屏/设备矩阵；已有报告保留原构建。
独立源分类与站区关系审核仍开放，当前修改不修改其结论。
