# 本机托管的地图字体与失败恢复

同一产品构建后续在[实际安装的 Chrome 与 Edge](installed-browser-checks.md)分别通过四组字体检查；本页保留最初接入与测量范围。

2026-10-27。地图名称以前完全依赖设备字体，无法保证中文覆盖，字体异常也没有分项提示。
当前为名称提供 `Railway Atlas CJK` 字体子集，失败仍保留轨道和设备字体回退，并可显式重试。
界面正文继续使用设备字体，本轮不宣称完成所有 UI/读屏/真实设备的字体验收。

## 字符覆盖与来源

子集从 Noto Sans CJK SC Regular 的固定提交生成，重新命名，保留原版权和 OFL 1.1 文本；
原件 SHA-256、提交、输入指纹、工具版本及最终字体指纹均记录在
[字体构建清单](../apps/web/client/public/map-font-manifest.json)。
官方源文件与许可来自[固定上游提交](https://github.com/notofonts/noto-cjk/tree/523d033d6cb47f4a80c58a35753646f5c3608a78)。
约 16 MB 原字体与构建工具轮子只存入被忽略的本地目录，仓库中的 WOFF2 子集为 129,992 字节，实际 cmap 含 501 个字符。

构建收集三份目录快照各自的 features.geojson、stations.geojson、lines.json，加上固定地图符号/制式后缀和可打印 ASCII。
用最终二进制的 cmap 独立核对这九份索引的名称字段，缺失字符为零。
这不保证任意未来名称或所有详情原始标签都被收录；新快照发布前须重新生成并执行 --check。
源字体缺少请求字符时构建直接失败，不能将不完整子集当作覆盖通过。

第一版生成脚本只读 features.geojson，遗漏独立车站索引。复核发现后补入车站、线路索引，
增加包含“仅在站点索引出现的字符”的测试；旧 99 KB 字体、旧性能和旧浏览器记录均已被最终版本替代，保留本地历史不冒充最终证据。

## 加载与交互

字体从与应用相同的来源加载，不向字体服务商发送请求。Fetch integrity 固定内容；
只有读取完整且 FontFace 解码成功才注册，并让车站、线路、设施和警示名称层优先使用该字体。
15 秒截止覆盖响应头、完整响应体和字体解码；父任务取消或迟到解码不能注册字体。
字体加载与地图数据并行，等待期间轨道仍能绘制，错误后显示设备字体回退说明及独立重试。

重试显示“正在恢复”，成功后使用公开 setGlyphs(null) 清除已栅格化的回退字形缓存，
保留画布、相机和分享 URL；销毁地图时取消请求并注销所属 FontFace。
关于数据提供字体来源/构建记录及原许可入口。
性能标记记录字体状态；字体加载中或错误的样本不能被正常性能守卫接受。

## 构建与许可复现

```powershell
python scripts/fetch_map_font.py
python -m venv data/manifests/local/font-build/venv
data/manifests/local/font-build/venv/Scripts/python.exe -m pip install --no-index --find-links data/manifests/local/font-build --require-hashes -r requirements-fonts.lock
data/manifests/local/font-build/venv/Scripts/python.exe scripts/build_map_font.py --check
```

字体工具使用隔离环境，不修改数据提取环境。固定的 fontTools 4.67.0 / Brotli 1.2.1 轮子、元数据及原许可文本纳入中央依赖清单。
两项新增工具的 OSV 查询当时无已知公告；这不是全应用的重新审计，也不替代 Brotli 原生轮子/其他工具层的发布审查。
中央清单现有 204 项组件、116 份许可文本，已知正文缺口为零；仍不代表法律授权审核、应用代码许可已选定或完整 N08 已完成。

最终构建、测量、直接 cmap 覆盖与故障报告见[字体接入证据](evidence/map-font.json)。
