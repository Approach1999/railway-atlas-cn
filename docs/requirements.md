# 需求规格 · v1.0

状态：当前阶段实施基线。2026-10-22。技术依据见 [可行性报告](feasibility.md)。

## 1. 产品定义

Railway Atlas CN 是面向中国铁路基础设施的交互式地理地图。
用户可以沿真实位置探索轨道、车站和设施，了解地图记录的类型、状态与属性，追溯数据来源。
初始服务铁路爱好者、交通地理学习者和 OSM 数据检查者；不承担铁路作业或乘车决策依据。

核心使用场景：

1. 搜索“沈阳北站”，区分铁路站点、附近地铁站点，定位并查看记录。
2. 在沈阳站区逐级放大，查看主线、站场侧线及可识别的轨道设施。
3. 筛选地铁、有轨电车或 OSM 标注的停用/废弃/建设轨道，观察空间分布。
4. 分享选中的要素与视图，其他人能在同一数据版本复现所见。

## 2. 范围与阶段

全国是长期空间范围，不以东北命名或绑定目录结构。v1 的首个交付数据区为沈阳试验矩形，
不是沈阳市行政边界；其他区域在通过数据验收后加入区域目录。
全国阶段需要全国数据实测，不能通过拼接城市截图宣布完成。

| 阶段 | 必须交付 | 不在本阶段范围 |
| --- | --- | --- |
| 沈阳 v1 | 地理浏览、中文车站搜索、筛选、详情、分享、数据与许可页、桌面与手机布局 | 全国数据完整性、全线路关系闭包 |
| 东北扩展 | 辽宁/吉林/黑龙江覆盖说明、区域切换、边界去重、规模指标 | 全国吞吐量承诺 |
| 全国扩展 | 全国可用区域目录、低缩放概览、全国搜索入口、按需瓦片与索引 | 实时运行、票务、专业调度 |

历史时间轴、地铁式拓扑图、路线规划、列车实时位置、时刻表、账号、用户编辑、数据上传、商业服务不属于 v1。
保留已有废弃/停用标签的查看能力，不承诺还原历史某年的线路网络。

## 3. 功能要求

| 编号 | 要求 | 可执行验收条件 |
| --- | --- | --- |
| R01 | 地图平移、缩放、复位与区域选择 | 默认进入沈阳可用区域；复位恢复该区视图；未发布地区明确提示“暂无数据”，不显示成没有铁路 |
| R02 | 中文车站名称与别名搜索 | “沈阳”“沈阳北”“沈阳北站”均能找到对应铁路记录；至少 20 条结果上限并提示收窄；空查询不列出全部车站 |
| R03 | 搜索消歧 | 展示名称、制式/未知、区域与对象类别；沈阳铁路站点和同名地铁记录分别可选；不能只按名称自动合并 |
| R04 | 轨道类型筛选 | 铁路、地铁/轻轨、有轨电车可独立开关；类型未知单列；空筛选提供恢复默认入口；站点与轨道使用一致制式规则 |
| R05 | 生命周期筛选 | 当前标注、建设、规划、停用、废弃/拆除分别可筛；标签未知保持未知；状态与制式两个维度可组合 |
| R06 | 缩放分级 | 区域概览显示主干轨道；详细缩放显示站场与设施；放大出现的侧线不能改变搜索结果的实体身份 |
| R07 | 要素详情 | 点击轨道/车站/设施，显示名称或未命名、类型、原始状态、可用属性、OSM 链接、快照时间与要素 ID；缺失字段显示“未标注” |
| R08 | 车站定位 | 点击搜索结果定位到该对象并高亮；站区 outline 与代表点关联须有证据，不靠名称和距离强行合并 |
| R09 | 视图分享 | URL 编码区域、视图、筛选、所选要素、数据版本；刷新与打开分享链接恢复；旧版本失效时解释并提供最新版本入口 |
| R10 | 数据与许可 | 署名持续可访问；展示来源、快照、数据范围、处理规则版本、缺失说明和 ODbL；可打开当前版本溯源页 |
| R11 | 空白与失败 | 区分超出覆盖、筛选为空、缩放不足、下载失败和 WebGL 不支持；允许重试；不静默清空全部图层 |
| R12 | 可访问交互 | 键盘完成搜索、结果选择、筛选、关闭详情；有可见焦点和状态播报；移动端可从结果列表完成定位 |

## 4. 数据语义要求

- D01：轨道 segment 与运营线路 route 分离。一个 OSM way 片段不等于一条命名线路；
  同名多个 way 不能仅按名称并成“整条京哈线”。v1 保证片段级查询，线路关系作为后续增强。
- D02：几何来源为 node/way；relation 可能用于后续分组。跨区 relation 未完整时，不承诺线路拓扑与路径规划。
- D03：`railway=rail` 不自动等于国铁、客运、主线或高铁。
  高铁分类只使用可追溯的显式标签或经审核的规则，不能只凭限速或线路名称判断。
- D04：无停用标签的记录称“OSM 当前标注”，不称“已核实运营”。停用与废弃分别保留。
- D05：车站 node、站区 way、站台、stop_position、地铁出入口分别建模；车站“185 条”之类原始记录数不能宣传为独立站数。
- D06：保留源对象 ID、原始标签、快照、规则版本；不得推断缺失的限速、电气化、轨距与运营方。
- D07：几何保持 WGS84 源坐标；渲染投影与底图坐标适配独立实现，禁止静默混用坐标系。

## 5. 非功能要求与测量方法

以下是正式 v1 验收目标，**不是本次探针已经达到的线上指标**。

| 编号 | 目标 | 测量口径 |
| --- | --- | --- |
| N01 | 首个可用视图 ≤3 秒（桌面）、≤5 秒（手机） | 固定 Chrome 稳定版与一台真实中端 Android；冷缓存、10 Mbps 下行、100 ms RTT，各 10 次取 p95；包括可点击的首屏铁路 |
| N02 | 筛选反馈 p95 ≤100 ms，搜索返回 p95 ≤300 ms | 当前区域索引加载后，各 100 次操作；网络等待单独记录 |
| N03 | 连续平移帧间隔 p95 ≤33 ms | 固定沈阳站场 30 秒轨迹，桌面/手机分别采样；不以平均 FPS 代替卡顿指标 |
| N04 | 首屏自有资源传输 ≤2 MiB，单个 MVT gzip ≤500 KiB | JS/CSS/索引/首屏铁路瓦片；底图与字体另记；报告冷缓存资源明细，不预载全国 GeoJSON |
| N05 | 数据引用完整、身份唯一 | 每个发布区域 way 节点缺失为 0；同一快照 typed OSM ID 去重；重复发布生成一致逻辑内容 |
| N06 | 发布可回滚 | 版本化数据 URL 不变更；保留当前与上一通过版本；切换目录指针后 5 分钟内可恢复上一版本 |
| N07 | 数据真实性与安全 | 标签作为文本展示；详情无任意 HTML 注入；外链限允许协议；不采集用户精确位置 |
| N08 | 可审计依赖与构建 | 锁定依赖，构建检查与依赖审计无未处置 high/critical；记录工具链、输入/输出指纹与规则版本 |

## 6. 数据质量验收样本

人工锚点：沈阳铁路站点 `node/6179162407`，沈阳北铁路站点 `node/676578837`。
对照附近地铁“沈阳站” `node/13028356638`、“沈阳北站” `node/11224161741`。
ID 是本次快照证据，未来重建必须重新核验，不能假设永久不变。

验收覆盖 20 个站点/站区、20 个轨道片段（含站场、地铁、停用/废弃、桥隧），
记录源标签、地图展示、分类解释与偏差。两名独立审核者或两次相隔的人工复核签字，
严重错位、身份误合并与错误状态解释必须为 0；未达标时不发布该批次。

## 7. 发布边界

首版默认无登录、无定位授权、无数据写入。代码公开与地图公开上线分别验收。
正式底图来源、坐标对齐、署名和中国境内公开地图适用要求在发布前确认，
见 [实施计划](implementation-plan.md)；当前本机技术验证不能视为取得上线条件。

## 8. 需求来源与变更

明确输入：全国范围、先沈阳/东北、地理铁路图、关注 Rust 与前端 WASM 的可能性。
本文件其余细节是基于真实样本形成的 v1 产品决策。WASM 作为性能触发项而非功能要求。
变更时记录编号、原因、受影响文档与验收，不在实现过程中悄悄增加票务、历史或路由范围。
