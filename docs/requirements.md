# 需求规格 · v1.2

状态：当前阶段实施基线。2026-10-22 修订；产品阶段仍为 v1。技术依据见 [可行性报告](feasibility.md)，交互细节见 [设计](design.md)，数据与发布契约见 [架构](architecture.md)，线路配色见 [线路配色](line-colors.md)。

## 1. 产品定义

Railway Atlas CN 是面向中国铁路基础设施的交互式地理地图。
用户可以沿真实地理位置探索轨道、车站和设施，了解地图记录的类型、状态与属性，追溯数据来源。
初始服务铁路爱好者、交通地理学习者和 OSM 数据检查者；不承担铁路作业、调度、路线导航或乘车决策依据。
“真实位置”指地理坐标，不是设备定位；v1 不请求 GPS 或定位权限，也不提供列车实时位置、时刻表或运营状态保证。

核心使用场景：

1. 搜索“沈阳北站”，区分铁路站点、附近地铁站点，聚焦并查看记录。
2. 在沈阳站区逐级放大，查看主线、站场侧线及可识别的轨道设施。
3. 筛选地铁、有轨电车或 OSM 标注的停用/废弃/建设轨道，观察空间分布。
4. 分享选中的要素与视图，其他人能在同一数据版本复现所见；分享快照至少保留 12 个月。

## 2. 范围与阶段

全国是长期空间范围，不以东北命名或绑定目录结构。v1 的首个交付数据区为沈阳试验矩形，
不是沈阳市行政边界；其他区域在通过数据验收后加入区域目录。
全国阶段需要全国数据实测，不能通过拼接城市截图宣布完成。

v1 采用扩展设施集：站台、stop_position、地铁出入口、信号、道岔、平交道口、车挡、
机务段、车辆段、检修库、水塔、转车盘、扇形库等；按缩放分级显示，完整矩阵见 §3.1。
v1 同时提供线路等级配色与城市轨道线路配色：高速、普速、支线、专用线使用不同颜色，
地铁按运营方线路图或人工配置的线路色显示；规则见 §3.3 与 [线路配色](line-colors.md)。

| 阶段 | 必须交付 | 不在本阶段范围 |
| --- | --- | --- |
| 沈阳 v1 | 地理浏览、中文车站搜索、筛选、详情、分享、数据与许可页、扩展设施集、线路等级与线路配色、桌面/平板/手机布局 | 全国数据完整性、全线路关系闭包、按线路名搜索与线路详情 |
| 东北扩展 | 辽宁/吉林/黑龙江覆盖说明、区域切换、边界去重、规模指标 | 全国吞吐量承诺 |
| 全国扩展 | 全国可用区域目录、低缩放概览、全国搜索入口、按需瓦片与索引 | 实时运行、票务、专业调度 |

历史时间轴、地铁式拓扑图、路线规划、列车实时位置、时刻表、账号、用户编辑、数据上传、商业服务不属于 v1。
保留已有废弃/停用标签的查看能力，不承诺还原历史某年的线路网络。
v1 不承诺拼音、繁简转换、英文界面和按线路名搜索；这些若加入须另立需求。
线路色和线路名可用于地图识别与详情，但不等于提供按线路名搜索、线路详情页或完整线路网络浏览。

### 3.1 v1 数据范围矩阵

| 类别 | OSM 示例 | 显示 | 搜索 | 详情 | 控制 |
| --- | --- | --- | --- | --- | --- |
| 轨道 | `railway=rail/subway/light_rail/tram/...` | z4+ 分级 | 否 | 是 | 类型+状态 |
| 车站点/乘降所 | `railway=station/halt/tram_stop` node | 按缩放分级 | 是 | 是 | 车站图层 |
| 站区 | `railway=station` way / `public_transport=station` | 按缩放分级 | 是 | 是 | 车站图层 |
| 站台 | `railway=platform` / `public_transport=platform` | z≥14 | 否 | 是 | 设施细节 |
| stop_position | `public_transport=stop_position` / `railway=stop` | z≥15 | 否 | 是 | 设施细节 |
| 地铁出入口 | `railway=subway_entrance` | z≥15 | 否 | 是 | 设施细节 |
| 信号/道岔/平交道口/车挡 | `railway=signal/switch/level_crossing/buffer_stop` | z≥15 | 否 | 是 | 设施细节 |
| 机务段/车辆段/检修库/水塔/转车盘/扇形库 | `railway=depot/yard/works/maintenance/water_tower/turntable/roundhouse` | z≥14 面，z≥15 点 | 否 | 是 | 设施细节 |
| 桥隧 | `bridge=*` / `tunnel=*` on track | 随轨道 | 否 | 是（轨道属性） | 类型+状态 |
| 其他未列对象 | — | 不发布 | — | — | — |

显示阈值为初始规则，按 QA 调整；设施细节开关默认关闭。
命名设施 v1 不进入搜索索引；如后续加入，须扩展 R02/R03 并重新验收。
站点、站区、站台、stop_position、出入口分别建模，不合并身份；桥隧不是独立线路。
低缩放不得因设施开关隐藏必要轨道或车站。

详情字段按实体类别固定：轨道显示 service/usage、显式高铁标签、限速、电气化、轨距、桥隧、运营方；
车站显示名称/别名、制式、站点或站区、车站编码（若有）、关联对象与证据状态；
设施显示 facility_kind、名称、父车站/站区（若有）、制式/状态（有则）与可用属性。
以上字段缺失时显示“未标注”，不适用字段不显示。
轨道附加 `line_class`、`line_key`、`line_shared` 用于等级/线路配色；
线路色不改变对象身份，共线段按 §3.3 回退，不强行归入单一线路。

当前探针的提取过滤以 `railway=*` 为主；若站台/stop_position/站区仅带 `public_transport=*`
而无 `railway=*`，须在 P1 扩展提取与分类规则后才计入 v1 覆盖，不能据此宣称已支持。

### 3.2 制式、状态与搜索规则

| UI 分组 | 数据枚举 |
| --- | --- |
| 铁路 | `rail` |
| 地铁/轻轨 | `subway`, `light_rail` |
| 有轨电车 | `tram` |
| 其他轨道 | `other`（窄轨、磁浮、单轨、缆索等；具体成员由规则版本固定） |
| 制式未知 | `unknown` |
| 当前标注 | `mapped` |
| 建设 | `construction` |
| 规划 | `proposed` |
| 停用 | `disused` |
| 废弃 | `abandoned` |
| 拆除 | `razed` |
| 状态未知 | `unknown` |
| 状态冲突 | `conflict` |

`railway=rail` 不自动等于国铁、客运、主线或高铁；高铁仅由显式标签或登记在规则版本中的审核规则判定。
搜索别名来源固定为 `name`、`name:zh`、`alt_name`、`old_name`、`official_name`，分号拆分；
匹配前做 trim、NFKC、空白折叠与拉丁大小写折叠，v1 不做拼音/繁简转换。
排序规则：名称精确 > 别名精确 > 名称前缀 > 别名前缀 > 子串；同分按站点/站区优先于站台/出入口，
再按名称长度、typed ID 稳定排序。查询返回前 20 条，面板一次显示 6 行可滚动；超过 20 条提示收窄。
搜索不受当前筛选限制；被筛选隐藏的结果标注“当前筛选已隐藏”，并提供“清除筛选并聚焦”。

### 3.3 线路等级与配色规则

| 显示等级 | 判定 | 颜色 | 说明 |
| --- | --- | --- | --- |
| 高速铁路 | 显式 `highspeed=yes` 或审核规则命中 | `#C8102E` | 不按名称、限速推断 |
| 普速干线 | 显式 `usage=main` 且未标注高速 | `#1F5A8A` | 缺失标签不推断为干线 |
| 普速/未标注 | `railway=rail`，无 `usage=main`、无高速标注 | `#4F7FA6` | 图例写明“未标注” |
| 支线/站场线 | `usage=branch` 或 `service=spur/siding/crossover/yard` | `#A17A3F` | 站场线高缩放显示 |
| 专用线 | `usage=industrial` 或 `service=industrial` | `#6B4F3A` | 不推断产权/运营方 |
| 地铁/轻轨/有轨电车 | `rail_mode` 与线路身份 | 线路色或制式回退色 | 见下 |
| 其他/未知 | 无法可靠分类 | `#8A8F98` | 不强行归类 |

城市轨道线路色优先级：人工覆盖 > 运营方/线路配置 > OSM `colour` > 制式回退。
配置源为 [`config/line-colors.json`](../config/line-colors.json)，规则与人工填色流程见
[线路配色](line-colors.md)；
每条线路记录来源、核对日期与置信度（official/operator-map/manual/osm/fallback）。
沈阳地铁未公布统一标准色值时，使用运营方线路图取色并标记 `operator-map`，
不得写成“官方色值标准”。

共线段仅在唯一线路归属明确时使用线路色；多条线路共享时使用制式回退色并标注“共线”，
详情列出全部线路。线路色不写入瓦片；`line_class`/`line_key` 作为语义字段保留，
配色改版不要求重建数据。
生命周期用线型和透明度叠加：当前实线、建设短虚线、规划点线、停用/废弃/拆除中性色，
选中态用深蓝外描边 + 白色 halo，不替换线路色。
颜色不是唯一区分：图例、线路号、线型、悬停提示和详情必须同时可读。

## 4. 数据语义要求

- D01：轨道 segment 与运营线路 route 分离。一个 OSM way 片段不等于一条命名线路；
  同名多个 way 不能仅按名称并成“整条京哈线”。v1 保证片段级查询，线路关系作为后续增强。
- D02：几何来源为 node/way；relation 可能用于后续分组。跨区 relation 未完整时，不承诺线路拓扑与路径规划。
- D03：`railway=rail` 不自动等于国铁、客运、主线或高铁。
  高铁分类只使用可追溯的显式标签或登记在规则版本中的审核规则，不能只凭限速或线路名称判断。
- D04：无任何生命周期标签（建设、规划、停用、废弃、拆除）的记录称“OSM 当前标注”，不称“已核实运营”。
  停用、废弃、拆除分别保留；冲突时保留原标签并置 `conflict`。
- D05：车站 node、站区 way、站台、stop_position、地铁出入口、信号、道岔、机务段/车辆段/检修库/水塔等
  分别建模；原始记录数不能宣传为独立站数或独立设施数。
- D06：保留源对象 ID、`osm_version`、`osm_timestamp`、`osm_changeset`（有则）、原始标签、快照、规则版本；
  不得推断缺失的限速、电气化、轨距与运营方。
- D07：几何保持 WGS84 源坐标；渲染投影与底图坐标适配独立实现，禁止静默混用坐标系。
- D08：对象范围以 §3.1 为准；未列对象不得静默进入轨道/车站图层；
  新增设施类别须版本化映射、数据测试与人工样本验收。
- D09：车站/站区/站台/出入口的关联证据分级为 `confirmed`/`candidate`/`none`；
  relation、明确成员引用优先；名称和距离只生成候选；代表点算法与关联证据写入 manifest/详情。
- D10：线路身份与颜色来源必须可追溯：保存 `line_key`、operator、ref、route relation 成员关系、
  颜色来源、核对日期与置信度；官方色优先，运营方线路图/人工配置次之，OSM `colour` 再次，
  最后回退；共享段或关系不完整时不得伪装成唯一线路；配色配置版本化，不烘焙进瓦片。

## 5. 非功能要求与测量方法

以下是正式 v1 验收目标，**不是本次探针已经达到的线上指标**。

| 编号 | 目标 | 测量口径 |
| --- | --- | --- |
| N01 | 首个可用视图 ≤3 秒（桌面）、≤5 秒（手机/平板） | 桌面固定 Chrome 稳定版，Android 用 Chrome，iPhone 用 Safari，平板用其默认浏览器；一台真实中端 Android、一台 iPhone、一台平板；冷缓存、10 Mbps 下行、100 ms RTT；每设备至少 30 次冷启动，报告 median/p95/max；可用=地图可交互、首屏铁路可点击、搜索框可聚焦；搜索索引加载单独记录并计入首屏预算；记录精确浏览器/OS/设备型号 |
| N02 | 筛选反馈 p95 ≤100 ms，搜索返回 p95 ≤300 ms | 桌面基准机、中端 Android 与 iPhone 分别测试；区分冷索引加载与热查询；每设备热查询各 100 次；冷索引加载单独记录并计入首屏预算；网络等待单列 |
| N03 | 连续平移帧间隔 p95 ≤33 ms（30 fps 目标） | 固定沈阳站场 30 秒轨迹，桌面/中端 Android/iPhone/平板分别采样；同时报告掉帧率与 >50 ms 长任务；不以平均 FPS 代替 |
| N04 | 首屏自有资源传输 ≤2 MiB，单个 MVT gzip ≤500 KiB | JS/CSS/索引/配色配置/首屏铁路瓦片；MVT 增加 `line_key`/`line_class` 的字节影响计入预算；另报总传输（含底图/字体）与第三方请求数；冷缓存资源明细；不预载全国 GeoJSON；2 MiB@10 Mbps 约 1.7 秒，须验证剩余渲染预算 |
| N05 | 数据引用完整、身份唯一、可对账 | 每个发布区域 way 节点缺失为 0；relation 引用独立报告；同一快照 typed OSM ID 去重；输入输出数量对账，每个排除对象有规则原因；重复发布 canonical JSON（键排序、固定浮点精度）/语义哈希一致；几何无零长/重复点 |
| N06 | 发布可回滚、版本可分享 | 版本化数据 URL 不变更；保留至少 12 个月快照，当前与上一通过版本始终可切；current 指针 TTL ≤5 分钟；切换指针后 5 分钟内恢复上一版本；任何内容变更生成新 snapshot ID，禁止原地覆盖 |
| N07 | 数据真实性、隐私与安全 | 标签作为文本展示；详情无任意 HTML 注入；外链限允许协议；不采集设备定位/精确位置；默认无 Cookie/分析；第三方底图/字体请求列出并说明；CSP、Referrer-Policy、HTTPS；分享 URL 仅含用户主动分享的视图坐标 |
| N08 | 可审计依赖、许可与构建 | 锁定依赖；构建检查与依赖审计无未处置 high/critical，例外须有 owner/理由/到期；许可证清单覆盖 JS/Rust/字体/底图/数据；记录工具链、OS/容器、输入/输出指纹与规则版本；建议生成 SBOM |
| N09 | 可访问性 WCAG 2.2 AA | 键盘完成 R01/R02/R07/R09/R16 核心任务；NVDA 桌面与 VoiceOver iOS 抽测；ARIA combobox/listbox 与 live region；焦点陷阱/返回；200% 缩放不丢功能；prefers-reduced-motion；不依赖地图画布的站点/要素列表等价路径（WebGL 不可用时自动显示，其他情况可手动打开）；线路/图例非文本对比 ≥3:1，徽标文字 ≥4.5:1；颜色不是唯一编码，做红绿色觉缺陷抽测；触摸目标 ≥44×44 px |

## 6. 数据质量验收样本

人工锚点：沈阳铁路站点 `node/6179162407`，沈阳北铁路站点 `node/676578837`。
对照附近地铁“沈阳站” `node/13028356638`、“沈阳北站” `node/11224161741`。
ID 是本次快照证据，未来重建必须重新核验，不能假设永久不变。

验收覆盖 20 个站点/站区、20 个轨道片段（含站场、地铁、停用/废弃、桥隧），
并按 §3.1 每类设施至少 5 个样本（不足 5 个则覆盖全部并说明）。
线路配色另需：每条运营地铁线路至少 1 个区间/关系样本；高速、普速干线、普速/未标注、
支线/站场线、专用线各至少 5 个样本；共线段、缺失线路色、浅色线路各至少 1 个样本。
记录源标签、地图展示、分类解释与偏差。

发布批次须由两名独立审核者签字；同一人相隔复核只用于低风险修订，不能替代独立审核。
分歧由第三人/项目负责人裁决并记录。

严重错误定义为：站点身份误合并、站区与站点错误关联、制式或生命周期错误、
把设施当轨道绘制、错误线路色归属或在共线段强行单选一条线路、
位置偏差超过 100 m 或明显落在错误站区。严重错误必须为 0。
分类一致率目标 ≥95%（按制式/生命周期/区域分层抽样）；冲突样本 100% 人工复核。
未达标时不发布该批次。

输入输出对账：每个源 railway 对象要么发布，要么被命名规则排除并记录原因；数量必须对平，
不得静默丢弃。审核记录含 `feature_key`、源标签、预期分类、实际展示、结论、审核者与日期，
纳入发布证据。

## 7. 发布边界

首版默认无登录、无设备定位、无数据写入。代码公开与地图公开上线分别验收。
正式底图来源、坐标对齐、署名、第三方请求与隐私说明、代码/数据许可和中国境内公开地图适用要求
在发布前确认，见 [实施计划](implementation-plan.md)；当前本机技术验证不能视为取得上线条件。
线路色来源、官方色未公布时的 `confidence` 标注、线路名称/标志的商标使用也须在发布前确认；
不复制官方 logo。分享快照至少保留 12 个月；旧链接失效时必须解释并提供最新版本入口。
