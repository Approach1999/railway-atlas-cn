## 修改与对照

原清空搜索按钮宽约 38.84px，分享按钮宽 34px，底图重试按钮 32×36px，
部分折叠标题高 40px。390×844 的八种状态共有 28 次尺寸不足观测，不是 28 个独立控件。
扩大按钮与折叠标题后，再将输入框、下拉框纳入检查，发现主搜索输入框自身仍只有 41px 高：
八种状态中五次可见，均被新增检查检出。

在 `any-pointer:coarse` 下，按钮最小宽高、折叠标题及主搜索输入框最小高度统一为 44px。
支持触摸的混合设备也匹配这条规则，纯精细指针环境保留原布局。
复选框使用原生关联文字区域作为有效目标，保留原生勾选框尺寸。

## 最终检查

本机 Chrome 156.0.8078.48、Edge 156.0.4314.42 各顺序检查四个模拟触屏尺寸：
320×640、390×844、768×1024、667×375。
每个尺寸检查概览、搜索、数据版本展开、详情、分享、关于、文字列表、底图配置失败八种状态。
每浏览器 32 个状态、1,295 次控件矩形观测，测量对象均达到 44×44px，没有页面横向溢出。
实际触摸清空按钮扩大的边缘、远离小复选框的关联文字区域，各尺寸均响应并核对状态。
没有页面脚本错误或跨源页面请求；底图故障由本地配置 503 产生，不下载在线栅格瓦片。
严格类型检查与生产构建通过；仅修改 CSS，没有重复运行领域测试。

脚本检查布局中可见且可用的按钮、折叠标题、文字输入/下拉框及关联复选/单选标签。
这不是所有控件状态、行内链接、生成后的列表分享字段、遮挡/重叠、地图要素命中半径、
真实设备或读屏验收；混合设备规则也未由真实混合设备操作验证。
截图保留原生触摸后的短暂高亮，不作为颜色或焦点检查证据。
历史 Edge 实际 200% 与其他功能/性能证据保持原构建，不因本次样式修改自动升级为当前版本。

## 复现与证据

本地预览运行时设置 PLAYWRIGHT_MODULE、PREVIEW_EVIDENCE，选择 ATLAS_BROWSER_CHANNEL=chrome 或 msedge：

```powershell
node scripts/verify_touch_targets.cjs
```

`--observe` 仅保留单尺寸对照；不足时报告 fails-size。正式检查没有此参数，不足会失败退出。
两浏览器顺序运行，不与性能测量并发。
